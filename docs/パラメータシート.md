## 16. 構築問題履歴と解決

全ての問題は第3回構築で解決済み。詳細は `docs/詳細設計書.md` セクション10を参照。

| # | 問題 | 根本原因 | 解決方法 | 解決 |
|:---:|:---|:---|:---|:---:|
| 1 | VMがjapanwestに作成された | VNet(japaneast)と--location不一致 | 全リソースをjapanwestに統一 | ✅ |
| 2 | VMにPublic IP付与 | 別リージョン作成時の自動動作 | NIC事前作成方式に変更 | ✅ |
| 3 | Private DNS VNetリンク失敗 | `zone-link create` は無効コマンド | `link vnet create` に修正 | ✅ |
| 4 | App Gateway作成失敗 | WAFポリシー未作成でWAF_v2指定 | WAFポリシーを事前作成 | ✅ |
| 5 | SQL Server publicAccess=Enabled | `--enable-public-network false` 反映されず | 作成後に `az sql server update` で無効化 | ✅ |
| 6 | Storage TLS1_0 | `--min-tls-version` 未指定 | `--min-tls-version TLS1_2` を追加 | ✅ |
| 7 | VMがsubnet-appgwに配置 | パスワード内 `"` が az.cmd 引数パースを破壊 | パスワード変更 + NIC事前作成方式 | ✅ |
| 8 | VM PIP/NSG自動作成 | 同上（引数ズレ） | NIC事前作成でPIP/NSGなしを保証 | ✅ |
| 9 | WAF OWASP 3.2 追加失敗 | デフォルトルールと複数プライマリ不可 | DefaultRuleSet 2.1 をそのまま使用 | ✅ |
| 10 | App Gateway作成失敗 | subnet-appgw にVM誤配置 | #7解決でsubnet-appgw空きを確保 | ✅ |
| 11 | App GW rule create 失敗 | 複数プールで --address-pool 未指定 | rule update 方式に変更 | ✅ |
| 12 | App GW rule1 削除失敗 | 唯一ルール削除不可＋リスナー競合 | rule1 を update で PathBasedRouting に書換え | ✅ |
| 13 | `/api/*` が404 | App GatewayにAPI経路が未定義 | `pool-api` + `http-settings-api` + `rule-api` を追加 | ✅ |
| 14 | `/api/*` が502 | AppGW→apps:8080 の許可/ヘルス判定不足 | NSG許可 + カスタムプローブ設定 | ✅ |
