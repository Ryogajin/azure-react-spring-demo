## 1. システム概要

### 1.1 目的
セキュアな閉域網環境を構築し、外部からのアクセスをApplication Gatewayに一本化する。
フロントエンドVMは用途別（開発用/顧客確認用）に環境を分離し、バックエンドは共通の1台を利用する。

### 1.2 システム構成図

```
                         Internet
                            |
                      [App Gateway]  ← 唯一のPublic IP
                       WAF_v2 + WAFポリシー
                   /      |       \
              /dev/*   /client/*  /api/*
                |         |          |
        [keiryo-deb-web1] [keiryo-deb-web2] [keiryo-deb-apps]
              開発用 IIS+React   顧客確認用 IIS+React
              172.16.1.x         172.16.1.x      172.16.2.x:8080
                     \             /
                      \           /
                    （同一APIを利用）
                  [共通API Spring Boot]
                   172.16.2.x:8080
                   /    |        \
                  /     |         \
        [Azure SQL]  [Azure Files]  [NAT Gateway]
        PE:172.16.3.x PE:172.16.3.x  →Internet(Yahoo等)
```

## 3. NSG（Network Security Group）設計

### 3.1 nsg-frontend

| ルール名 | 優先度 | 方向 | アクション | プロトコル | 送信元 | 宛先ポート | 説明 |
|:---|:---:|:---|:---|:---|:---|:---:|:---|
| Allow-HTTP-from-AppGW | 100 | Inbound | Allow | TCP | 172.16.0.0/24 | 80 | App GWサブネットからのHTTP |
| Allow-GatewayManager | 110 | Inbound | Allow | TCP | GatewayManager | 65200-65535 | App GW管理ポート |

関連付け先: **subnet-frontend** (172.16.1.0/24)

### 3.2 nsg-backend

| ルール名 | 優先度 | 方向 | アクション | プロトコル | 送信元 | 宛先ポート | 説明 |

| Allow-API-from-Frontend | 100 | Inbound | Allow | TCP | 172.16.1.0/24 | 8080 | フロントエンドからのAPI通信 |
| Allow-API-from-AppGW | 110 | Inbound | Allow | TCP | 172.16.0.0/24 | 8080 | App GatewayからのAPI通信 |

関連付け先: **subnet-backend** (172.16.2.0/24)

### 3.3 nsg-data

| ルール名 | 優先度 | 方向 | アクション | プロトコル | 送信元 | 宛先ポート | 説明 |
|:---|:---:|:---|:---|:---|:---|:---:|:---|

| Allow-SMB-from-Backend | 110 | Inbound | Allow | TCP | 172.16.2.0/24 | 445 | バックエンドからのSMB通信 |

関連付け先: **subnet-data** (172.16.3.0/24)

                   HTTP(8080)
                          │

                    │  │  │
          ┌─────────┘  │  └──────────┐

## 10. 構築の問題履歴と解決

### 10.1 第1回構築（japaneast）の問題

| # | 問題 | 原因 | 修正 | 解決 |
|:---:|:---|:---|:---|:---:|
| 1 | VMがjapanwestに作成された | VNet(japaneast)と--location不一致 | 全リソースをjapanwestに統一 | ✅ |
| 2 | VMにPublic IP付与 | 別リージョン作成時の自動動作 | NIC事前作成方式に変更 | ✅ |
| 3 | Private DNS VNetリンク失敗 | `zone-link create` は無効コマンド | `link vnet create` に修正 | ✅ |
| 4 | App Gateway作成失敗 | WAFポリシー未作成でWAF_v2指定 | WAFポリシーを事前作成 | ✅ |
| 5 | SQL Server publicAccess=Enabled | `--enable-public-network false` が反映されない | 作成後に `az sql server update` で無効化 | ✅ |
| 6 | Storage Account TLS1_0 | `--min-tls-version` 未指定 | `--min-tls-version TLS1_2` を追加 | ✅ |

### 10.2 第2回構築（japanwest）の問題

| # | 問題 | 原因 | 修正 | 解決 |
|:---:|:---|:---|:---|:---:|
| 7 | VMが全てsubnet-appgwに配置 | パスワード内の `"` が `az.cmd` の引数パースを壊し `--nics` `--subnet` が無視された | パスワードから `"` を除去 + NIC事前作成方式 | ✅ |
| 8 | VMにPublic IPと個別NSGが自動作成 | 同上（引数ズレで `--public-ip-address ""` `--nsg ""` も無視） | NIC事前作成でPIP/NSGなしを保証 | ✅ |
| 9 | WAF OWASP 3.2 追加失敗 | デフォルト DefaultRuleSet 2.1 が自動適用、複数プライマリ不可 | DefaultRuleSet 2.1 をそのまま使用（開発環境で十分） | ✅ |
| 10 | App Gateway作成失敗 | subnet-appgw にVMが誤配置され専用サブネット要件違反 | #7の修正でVM正常配置、subnet-appgw空きを確保 | ✅ |

### 10.3 第3回構築で追加修正した項目

| # | 問題 | 原因 | 修正 | 解決 |
|:---:|:---|:---|:---|:---:|
| 11 | App GW rule create 失敗 | 複数バックエンドプールで `--address-pool` 未指定 | `rule update` 方式に変更（デフォルトrule1をPathBasedRoutingに更新） | ✅ |
| 12 | App GW rule1 削除失敗 | 唯一のルールは削除不可、かつリスナー競合で新規作成も不可 | rule1 を削除せず update で書き換え | ✅ |
| 13 | App GW経由 `/api/*` が404 | `/api/*` がIIS側に到達し、APIバックエンドへの経路が未定義 | `pool-api` + `http-settings-api` + `rule-api` を追加 | ✅ |
