# STEP2〜STEP5 実施サマリー（2026-02-24）

## 1. 実施目的
- Azure基盤（STEP1）上に、バックエンド/フロントエンドを配置し、App Gateway公開IPのみで外部利用できる状態にする。

## 2. 実施結果（要約）
- `keiryo-deb-apps` に Spring Boot API を配置し、`KeiryoAPI` サービスで常駐化。
- `keiryo-deb-web1` に `/dev/` 用React、`keiryo-deb-web2` に `/client/` 用ReactをIIS配置。
- App Gatewayで `/dev/*` `/client/*` `/api/*` のパスベースルーティングを確立。
- `https://20.89.245.247/dev/` / `https://20.89.245.247/client/` / `https://20.89.245.247/api/health` で動作確認。

## 3. STEP2 バックエンド（Spring Boot）実施内容
- ローカルで `mvn clean package -DskipTests` を実行し JAR作成。
- apps VM に `C:\app\keiryo-api-1.0.0.jar` と `C:\app\config\application.properties` を配置。
- `nssm` で Windows サービス `KeiryoAPI` を作成・自動起動化。
- Javaパス不一致でサービス起動失敗が発生し、`(Get-Command java).Source` の実パスに修正して解消。
- health確認:
  - `Invoke-RestMethod http://localhost:8080/api/health`
  - 期待値: `app=UP`, `database=UP`

## 4. STEP3 フロントエンド（React）実施内容
- API呼び出しを同一オリジンに統一（`VITE_API_BASE_URL=`）。
- `App.tsx` で `BrowserRouter basename` を `import.meta.env.BASE_URL` に統一。
- ビルドコマンドを用途別に固定:
  - `npm run build:dev`（`--base=/dev/`）
  - `npm run build:client`（`--base=/client/`）
- `/dev` と `/client` の成果物取り違えによる白画面は、再ビルド・再配置で解消。

## 5. STEP4 Windows Server配置（IIS）実施内容
- web1: `C:\inetpub\wwwroot\dev` に dev成果物展開。
- web2: `C:\inetpub\wwwroot\client` に client成果物展開。
- `web.config` に SPA向け URL Rewrite を設定（`/dev/*` と `/client/*` を各 `index.html` に書き換え）。
- 404（`C:\inetpub\wwwroot\client\login` を探す事象）は Rewriteルール追加で解消。

## 6. STEP5 テスト・不具合対応実施内容
- web2→apps の疎通不可を解消:
  - Windows Firewall 8080許可
  - `nsg-backend` に frontend→apps:8080 許可
- CORSエラーを解消:
  - `CorsConfig.java` で `localhost` / frontend IP / AppGW Public IP を許可
- UI中央寄せ対応:
  - `DashboardPage.tsx` / `LoginPage.tsx` / `index.css` を調整
- App Gateway API公開対応:
  - `pool-api` / `http-settings-api` / `rule-api (/api/*)` を追加
  - `nsg-backend` に AppGWサブネット(172.16.0.0/24)→8080 を許可
  - `probe-api-health` を作成し `http-settings-api` に紐付け
  - 502 Bad Gateway を解消
